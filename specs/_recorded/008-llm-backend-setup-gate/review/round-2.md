#### [AMBIGUOUS_REQUIREMENT] ADVISORY
- Location: `platform/backend-setup-gate/spec.md` § Scenario: Re-checking shows that it is checking and answers once (fourth *AND*); `plan.md` § Verification § Scenario Coverage (that scenario's test name)
- Issue: the scenario's third and fourth assertions over-constrain each other. The third removes the control while a probe is unsettled, »so a second activation cannot start a second probe«. The fourth then describes a race the third makes unreachable: »an answer from a probe the shell has stopped waiting on — **superseded by a re-check** or abandoned by an unmount — MUST NOT reach the screen, so only the newest answer renders **whichever order two probes settle in**«. With the control off screen until the first probe settles, two probes are never in flight together through the shell's own surface, and `locale` is excluded from the effect's dependency list, so nothing else re-runs it. Only the unmount half is reachable — and that half is already required by task 10's pre-existing »Abandon a probe whose result arrives after unmount« clause.

  The mapped test name promises the unreachable half: `shows the checking state on a re-check, hides the fault text with the control, and renders only the newest answer`. An implementer can assert the first two clauses and cannot construct two overlapping probes to assert the third. Round 1's fix guidance asked for one of the two rules — »(or that only the newest probe's answer is rendered — pick one and state it)« — and both were written. The invariant is still worth implementing as defence in depth, and task 10 states its mechanism clearly; what is wrong is asserting it in a scenario, where every clause is meant to be falsifiable by a test.
- Fix: In `platform/backend-setup-gate/spec.md`, narrow the fourth *AND* to the reachable case — an answer from a probe the shell abandoned at unmount MUST NOT reach the screen — and drop »superseded by a re-check« and »whichever order two probes settle in« from the scenario. Keep the supersede rule where it is implementable and unfalsifiable-by-design: task 10's cleanup sentence, which already carries it. Change the § Verification § Scenario Coverage test name for this scenario to drop »and renders only the newest answer«, replacing it with the assertion a test can actually make against the abandoned-probe case.
