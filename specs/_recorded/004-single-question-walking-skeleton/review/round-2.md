## Feasibility

#### [NFR_IGNORED] BLOCKER

- Location: `plan.md` § Implementation Tasks task 4, the guard sentence; § Key interfaces, the process-local paragraph; `decision-log.md` § [6a]; `interview/single-question-interview/spec.md` scenarios `Two concurrent requests for the opening question reach the model once` and `A question the caller abandons is never stored`
- Issue: the new guard shares one production across callers while the model stream stays bound to one caller's signal, and nothing says how the two interact. Task 4 specifies both halves in one paragraph: the generator "streams `deps.llm.stream(conversation, signal)` … skipping the save when the signal is aborted", and "a request that finds an entry awaits it and replays its result instead of reaching the model, and the entry is deleted once the promise settles either way". The entry therefore outlives its owner's abort, and the reload the guard exists for is precisely that interleaving — § Manual Testing's `pnpm dev` reload drops connection 1 (an abort) at the moment connection 2 arrives. Both readings break a stated requirement. If the owner's abort ends the shared model stream and the promise resolves with the text accumulated so far, the waiting caller receives a truncated question, its route writes `done` for a question task 4 explicitly did not save, and § Requirements' "A client that observed `done` and reloads MUST see the same question" fails — the reload shows different text. If the promise instead rejects, the waiting caller receives an `error` frame though nothing failed, and `A question the caller abandons is never stored`'s "the abandoned stream MUST NOT reject" no longer says which caller it binds. No scenario, task, or decision names the case, so the implementer invents it inside an `[expert]` task.
- Fix: In `plan.md` task 4, state that the shared production is driven by an interview-owned `AbortController` rather than by any one caller's signal: a caller's own `signal` ends only that caller's iteration, and the controller is aborted only once every caller sharing the production has abandoned it, so the single-caller abort case behaves exactly as `A question the caller abandons is never stored` already requires. State in the same task that the shared promise resolves only after `save` resolved, so every caller that receives text receives a stored question. Add the scenario `A caller that abandons a shared question production leaves the other caller's question intact` to `interview/single-question-interview/spec.md` — GIVEN two callers on one in-flight production, WHEN the first abandons its stream, THEN the second MUST receive the whole question, the store MUST hold exactly one turn, and the model MUST have been reached once — extend task 3 to cover it, add the § Verification row, and record the rule in `decision-log.md` § [6a]. If the reference-counted controller is judged too much machinery, write the opposite rule explicitly instead: the shared promise rejects when its owner abandons, the map entry is deleted, and the waiting caller's route writes an `error` frame; then write the new scenario against that outcome and say so in § [6a].

## Requirement Quality

#### [AMBIGUOUS_REQUIREMENT] BLOCKER

- Location: `plan.md` § Implementation Tasks task 1, "Add a `state.test-d.ts` whose `@ts-expect-error` targets what the tag actually excludes … and confirm each directive is consumed rather than reported as unused"
- Issue: one of the two directives cannot be consumed where it is naturally written. Compiled with `tsconfig.base.json` against the exact `AskedTurn`/`AnsweredTurn` declarations of § Key interfaces, a multi-line literal `const t: Turn = { status: 'asked', question, askedAt, answer }` with the directive above the `const` produces two errors, not zero: `error TS2578: Unused '@ts-expect-error' directive` on the directive's line, and `error TS2353: Object literal may only specify known properties, and 'answer' does not exist in type 'AskedTurn'` on the `answer:` line — TypeScript attributes the excess-property error to the offending property, which the directive above the declaration does not cover. The `status: 'answered'` case is unaffected, because a missing required property is reported on the declaration line. `packages/core/vitest.config.ts` sets `typecheck.enabled`, and `packages/core/tsconfig.json` includes `src/**/*.ts`, so the file fails both `pnpm test` and `pnpm typecheck`. Writing the literal on one line does compile, but that line is 94 characters and the repository's `.prettierrc` sets only `singleQuote` and `trailingComma`, leaving Prettier's 80-column default to re-break it — so the § Checklist `Format` row undoes the workaround. As written, task 1 reproduces the round-1 failure mode it was revised to remove: a red bar whose obvious reading is that the tagged union does not exclude the literal.
- Fix: In `plan.md` task 1, state that the stray-`answer` directive is written immediately above the `answer` property inside the object literal rather than above the `const`, because `tsc` reports the excess-property error on the property's own line, and that a single-line literal is not an alternative because Prettier's 80-column default re-breaks it. Leave the `status: 'answered'` directive above its declaration, where it is consumed.
